# ReviewPort v5.6.0 發布報告

> **發布狀態：發布候選版已打包。** 本版修正重點是：精確星等掃描不再只相信 UI 選取文字，而是以 TikTok 頁面已顯示的「該星等數量」與「目前顯示結果數」作數值確認。任何無法確認的狀態都會 fail-closed 暫停，絕不退回掃描全部星等。

## 1. 使用者可見改善

| 領域 | v5.6 行為 | 對使用者的意義 |
|---|---|---|
| 精確 1–5 星掃描 | 選取原生星等後，必須確認目前結果數等於該星等 histogram 數 | 避免 `★ 1` 已顯示但實際仍混入其他星等，或錯掃全部評論。 |
| 首頁 0 scanned 修正 | 若已確認單星結果但 TikTok 未提供可觀察 response，只在限定的可見評論區擷取首頁卡片 | 可收集已確定的首批篩選結果；不使用未篩選 SSR。 |
| 掃描目標 | popup 改為 **Reviews to collect**，頁數只保留在內部推導與 100 頁安全上限 | 使用者以想要的評論數量操作，不必估算 TikTok 頁數。 |
| 報告背景 | Review Studio 顯示已保存數、TikTok 公開分母、目標與時間戳 | 使用者可辨識已保存的是樣本還是完整匹配集。 |
| 商品資料 | TikTok 商品規格顯示為 **Variant**，不再暗示它是 Shopify SKU | 不會把 TikTok 規格偽裝為 Shopify 商品匹配值。 |
| 圖片與 Shopify | 匯出前繼續顯示不相容、超額或不公開圖片 URL 的跳過預檢 | 買家可在下載前理解 CSV 圖片限制；不會虛構可用 URL。 |

## 2. 精確星等的安全確認契約

當最低與最高星等相同時，ReviewPort 的順序如下：

1. 以 TikTok 可見的原生星等控制項選擇指定星等；支援星形裝飾、英文和繁中／中文數字顯示作為控制操作訊號。
2. 從限定評論區讀取可見 rating histogram 與目前結果／總數。
3. 只有在目前結果數等於目標星等 histogram 數時，才視為篩選已確認並開始收集。
4. 優先處理受限、第一方 TikTok Shop review-list response。當首頁沒有相容 response 時，才在**已確認且目前可見的篩選評論區**擷取卡片。
5. 卡片資料仍須通過實際星等、日期、內容和本機 fingerprint 去重檢查；星等不符、無法安全解析或未確認篩選都會被拒絕。

這項設計保持了以下原則：**不繞過 TikTok 驗證、不修改請求／回應、不讀取未篩選 SSR 來填補精確星等結果、不以全頁自由文字掃描取代限定評論區。**

## 3. 版本中的資料與匯出規則

| 資料 | v5.6 規則 |
|---|---|
| Username | 原樣保留 TikTok 遮罩名稱；不生成假名。 |
| Description | 保留完整、多段可見評論內容；不縮成第一段。 |
| Rating | 寫入卡片或受限 response 實際 rating；不符目標星等者拒絕。 |
| Date | UTC 正規化，保留 exporter 相容格式。 |
| Variant | 保存 TikTok `Product:`、`商品:`、`Item:` 或等效可見規格；不作為 Shopify SKU。 |
| Country／verified | 只在 TikTok 明確提供時保存與輸出；不自行標示 verified buyer。 |
| Photo URLs | 以 array 保存；Custom CSV 保留原始已收集 URL。嚴格 Shopify 格式只接受公開支援圖片，並套用格式圖片上限。 |
| Shopify matching | 格式需要時必須由商家提供 Shopify product handle 或 Product ID；TikTok Variant 不可代替。 |

## 5. 真實頁面實測限制與建議

在本環境中已以指定 TikTok Shop 商品頁進行只讀 DOM 結構觀察，並使用保存的中文／英文頁面統計 fixture 驗證數值契約。新版本沒有辦法在使用者目前載入的舊 extension 實例上自動重載，因此仍需要在 Chrome 中以 v5.6 ZIP 重新載入 extension 後，手動進行最後相容性驗收。

建議按以下順序驗收：先確認 exact 1-star 顯示的 matching count 與 histogram 數一致；確認 popup 開始產生首批已掃描評論而非 0；接著測試 2–3 頁以上資料、Pause、Resume、Stop、手動 TikTok verification 後 Resume，以及有／沒有買家照片的資料。若頁面結構或 TikTok response path 有變動，應以 popup 中保存的 selector／metric diagnostics 建立新的 fixture，再修正 selector registry；不要放寬成掃描全部星等。

## 7. 後續維護規則

請維持「先重現、再修正」的流程。任何 selector、review-list path 或本機解析變更，都應新增相應 fixture 與回歸測試。不要移除精確星等的 histogram／結果數確認，不要將 TikTok Variant 當 Shopify SKU，不要偽造 username、email、verified buyer、日期或圖片 URL，也不要提供 CAPTCHA 或其他驗證繞過方式。
